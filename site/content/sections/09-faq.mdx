<Accordion title="How does Reylo compare with sqlc, PgTyped and other tools?" id="faq-compare">

[Comparison](/compare) shows what Reylo and seven other tools that type SQL infer: nullability, parameters, cardinality and nested JSON.

</Accordion>
<Accordion title="Does the type check run my queries?" id="faq-run-queries">

No. Reylo has your database prepare each query, which checks it and describes its parameters and columns without running it, and reads the rest from the catalog. On SQLite, Reylo prepares the query in its own copy of SQLite, from the schema in your database file.

</Accordion>
<Accordion title="Does Reylo run migrations?" id="faq-migrations">

Not at the moment: bring your own. Reylo types your queries against whatever schema your dev database has, so apply your migrations with the tool you already use, such as Prisma Migrate, Drizzle Kit, Atlas, dbmate or plain SQL files. After a migration, the next type check sees the new schema: a dropped column is an error in the `.sql` file that names it, and in the code that reads it.

</Accordion>
<Accordion title="How do I type-check in CI?" id="in-ci">

Start the database, apply the migrations, and run `tsc --noEmit --runExternalCode` with `DATABASE_URL` set. Your tests need the database too. [`direct_url`](/configuration#direct_url) names the database it reads. To skip analyzing what hasn't changed, keep `.reylo/` in your CI's cache: a database built by the same migrations reads its entries. Before Reylo 0.8.0, a Postgres built with JIT, as most Docker images are, can make the type check take minutes: add `?options=-c%20jit%3Doff` to its URL. [CI](/ci) has a complete GitHub Actions workflow.

</Accordion>
<Accordion title="How do I move a project from Prisma?" id="faq-prisma">

Keep Prisma Migrate for your schema, and turn each Prisma Client call into a `.sql` file. [Migrating from Prisma](/prisma) covers the schema changes to make first, the build, each call as SQL, and what to check before you finish.

</Accordion>
<Accordion title="Can another tool read the types Reylo infers?" id="faq-rtd">

Yes: [`analyze()`](/typedefs#usage) returns each statement's parameters, columns, types and cardinality as JSON, in Reylo Type Defs, and `reylo analyze` prints the same from a shell. The format is in preview, and may change in any release until 1.0.0.

</Accordion>
<Accordion title="What is the .reylo directory, and should I commit it?" id="faq-reylo-directory">

It is Reylo's cache of each query's analysis. It has its own `.gitignore`, so git skips it: don't commit it.

</Accordion>
<Accordion title="Can I build without a database?" id="faq-no-database">

Yes, where `.reylo/` already holds each query's analysis. A type check or a build that can't reach the database reads its types from there, and says so: every build step prints one line, and a query's hover shows it.

```txt
reylo: cannot connect to the database at localhost:5432/app (DATABASE_URL in .env): connection refused; building from .reylo/, analyzed 2026-11-07
```

The types are then as old as that analysis, so a migration since doesn't show. With a server's URL set, a build reads only what was analyzed on that database. With none, or where the database is a file, as on SQLite and DuckDB, it reads the newest analysis of any. A query that `.reylo/` doesn't hold is an error.

A host that builds before it migrates, such as Vercel, starts with no `.reylo/`, so build against a database of its own there:

1. Create an empty database.
2. Run your migrations into it, which also tries each one before it reaches production.
3. Run the build with [`direct_url`](/configuration#direct_url) pointed at that database.
4. Drop it.
5. Migrate your deployment's own database.

</Accordion>
<Accordion title="Why are dates strings, and 64-bit integers bigints?" id="faq-value-types">

Reylo decodes its own queries' values itself, so every driver gives the same types. A 64-bit integer is a `bigint`, since a `number` loses precision past 2^53; a decimal is its exact text; and an instant is its ISO 8601 text in UTC. No value is a `Date`, which a driver reads in a time zone nobody chose. Every SQL type's TypeScript type is in [Inference](/inference#primitives).

</Accordion>
<Accordion title="How do I add observability to my queries?" id="faq-observability">

Reylo publishes every query it runs on Node's tracing channel `reylo:query`, so your tracer, logger or other o11y tool can wrap each one in a span. [Tracing](/observability) shows how.

</Accordion>
