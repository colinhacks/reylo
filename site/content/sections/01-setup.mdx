## Setup

To install Reylo, you'll need:

- **TypeScript 7.1 (currently in beta).** The first release with content mappers.
- **Node 24 or later.**
- **A running dev database.** Reylo reads your current schema from it ([Database](#database) points Reylo at it):
  - **Postgres** 14 to 18, including Neon and PGlite
  - **MySQL** 8.0.22 or later, including PlanetScale
  - **SQLite**, including Cloudflare D1 and Durable Objects, Turso and libSQL

Then set Reylo up in six steps:

<div className="dk-steps">

### Install

Install Reylo, the engine for your database and TypeScript 7.1:

```sh
npm install reylo
npm install -D @reylosql/postgres  # or mysql, sqlite
npm install -D typescript@beta
```

### TypeScript

Add Reylo to `tsconfig.json`, for `.sql` files and for its project file, `.reylo.yaml` or `.reylo.yml`:

```jsonc title="tsconfig.json"
{
  "compilerOptions": { /* ... */ },
  "contentMappers": [ // [!code ++]
    { "package": "reylo", "extensions": [".sql", ".reylo.yaml", ".reylo.yml"] } // [!code ++]
  ] // [!code ++]
}
```

Then type-check with `--runExternalCode`, which lets `tsc` run content mappers:

```jsonc title="package.json"
{
  "scripts": {
    "typecheck": "tsc --noEmit --runExternalCode" // [!code ++]
  }
}
```

### Runtime / framework [#plugins]

Install the plugin for your runtime or framework of choice:

<Tabs items={["Node", "Bun", "Nub", "Vite", "Next.js", "esbuild", "webpack", "Rspack", "Cloudflare", "Jest"]}>
<Tab value="Node" id="setup-node">

Load Reylo's preload with `--import`:

```sh
node --env-file=.env --import reylo/register main.ts
```

</Tab>
<Tab value="Bun" id="setup-bun">

Add the preload to `bunfig.toml`, and under `[test]` for `bun test`:

```toml title="bunfig.toml"
preload = ["reylo/register"]

[test]
preload = ["reylo/register"]
```

For Bun's bundler, use the esbuild plugin:

```ts title="build.ts"
import reylo from "reylo/esbuild";

await Bun.build({
  entrypoints: ["main.ts"],
  target: "bun",
  plugins: [reylo()],
  outdir: "dist",
});
```

</Tab>
<Tab value="Nub" id="setup-nub">

Add the preload to `nub.jsonc`:

```jsonc title="nub.jsonc"
{
  "preload": ["reylo/register"]
}
```

</Tab>
<Tab value="Vite" id="setup-vite">

Add Reylo's plugin to your Vite config:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import reylo from "reylo/vite";

export default defineConfig({
  plugins: [reylo()],
});
```

Import `.sql` files from server code only, such as a `.server/` directory: Vite bundles a query wherever it is imported, the browser included. For Vitest, this plugin is all you need.

</Tab>
<Tab value="Next.js" id="setup-nextjs">

Wrap your Next.js config with `withReylo`:

```ts title="next.config.ts"
import type { NextConfig } from "next";
import { withReylo } from "reylo/next";

const nextConfig: NextConfig = {
  // ...
};

export default withReylo(nextConfig);
```

Your server code can now import `.sql` files, with Turbopack or webpack, and `next build` fails on a type error in a query or its caller.

To type-check without building, run `next typegen` first, which writes the route types:

```json title="package.json"
{
  "scripts": {
    "typecheck": "next typegen && tsc --noEmit --runExternalCode"
  }
}
```

<Details summary="How the build checks the types" id="nextjs-type-check">

Next.js type-checks with your project's `tsc` but without `--runExternalCode`, so `withReylo` turns that check off and runs `tsc --noEmit --runExternalCode` itself, after the compile and before the prerender. Next.js still prints "Skipping validation of types" for its own check.

</Details>

</Tab>
<Tab value="esbuild" id="setup-esbuild">

Add Reylo's plugin to your esbuild build:

```js title="build.mjs"
import * as esbuild from "esbuild";
import reylo from "reylo/esbuild";

await esbuild.build({
  entryPoints: ["main.ts"],
  bundle: true,
  platform: "node",
  format: "esm",
  plugins: [reylo()],
  outfile: "dist/main.mjs",
});
```

</Tab>
<Tab value="webpack" id="setup-webpack">

Load `.sql` files with Reylo's loader in your webpack config:

```js title="webpack.config.mjs"
export default {
  // ...
  module: {
    rules: [{ test: /\.sql$/, use: "reylo/webpack" }],
  },
};
```

Compile TypeScript with `swc-loader` or `babel-loader`, since TypeScript 7 has no JavaScript API for `ts-loader`.

</Tab>
<Tab value="Rspack" id="setup-rspack">

Load `.sql` files with Reylo's webpack loader in your Rspack config:

```js title="rspack.config.mjs"
export default {
  // ...
  module: {
    rules: [{ test: /\.sql$/, use: "reylo/webpack" }],
  },

```

</Tab>
<Tab value="Cloudflare" id="setup-cloudflare-workers">

Add Reylo's Vite plugin beside Cloudflare's:

```ts title="vite.config.ts"
import { cloudflare } from "@cloudflare/vite-plugin";
import { defineConfig } from "vite";
import reylo from "reylo/vite";

export default defineConfig({
  plugins: [reylo(), cloudflare()],
});
```

Pass the D1 binding as the client, as in `getUser.run(env.DB, { id: 1 })`; you don't need `nodejs_compat`. For the type check, set [`direct_url`](#direct_url) in `.reylo.yaml` to the local D1 file that `wrangler d1 migrations apply --local` creates. Don't set it in `.env`, which Wrangler loads into the Worker as secrets.

</Tab>
<Tab value="Jest" id="setup-jest">

Add Reylo's transformer to your Jest config:

```js title="jest.config.js"
export default {
  transform: { "\\.sql$": "reylo/jest" },
  extensionsToTreatAsEsm: [".sql"],
};
```

```sh
# Jest runs ES modules only behind this Node flag
NODE_OPTIONS=--experimental-vm-modules npx jest
```

### Database

**Reylo requires a connection to a live dev database.** It retrieves the types of each compiled query, its parameters and its columns, from the database itself. Reylo finds your dev database through the `DATABASE_URL` environment variable, and the URL's scheme tells it which database you use:

```sh title=".env" tab="Postgres" tab-group="dialect"
# or postgresql://
DATABASE_URL=postgres://localhost:5432/app
```

```sh title=".env" tab="MySQL" tab-group="dialect"
# or mariadb://
DATABASE_URL=mysql://root@localhost:3306/app
```

```sh title=".env" tab="SQLite" tab-group="dialect"
# or sqlite:; the path starts at package.json
DATABASE_URL=file:./app.db
```

To override this, create a `.reylo.yaml` file in your project root and set the `direct_url` field:

```yaml title=".reylo.yaml"
direct_url: postgres://localhost:5432/app
```

You can also reference other environment variables via string interpolation:

```yaml title=".reylo.yaml"
direct_url: ${APP_DATABASE_URL}
```

Or specify a set of `.env` files to load:

```yaml title=".reylo.yaml"
# the default is [.env.local, .env]
env: [.env.development, .env]
```

### Editor [#editors]

Set up your editor to use the TypeScript 7.1 language server, with content mappers on. Then a hover over a query shows its types, its SQL and the comment at the top of its `.sql` file, an error in a `.sql` file is underlined where it is, and go-to-definition on a query opens its `.sql` file.

<Tabs items={["VS Code", "Cursor", "Zed"]}>
<Tab value="VS Code" id="editor-vscode">

1. Install the **TypeScript 7** extension (`TypeScriptTeam.native-preview`).
2. Point it at the project's TypeScript: the extension's own copy is TypeScript 7.0, which has no content mappers.

   ```json title=".vscode/settings.json"
   {
     "js/ts.experimental.useTsgo": true,
     "js/ts.tsdk.path": "./node_modules/typescript"
   }
   ```

3. Trust the workspace, and click **Allow** when the extension asks to use the workspace's TypeScript. Content mappers run in a trusted workspace only. Missed it? It waits under the bell in the status bar, or **Developer: Reload Window** asks again.

Keep `DATABASE_URL` in `.env`: the editor doesn't see your shell's environment.

</Tab>

1. Install the **TypeScript Language Server** extension by Zed Industries (search for "tsgo").
2. Point it at the project's TypeScript, with content mappers on:

   ```jsonc title=".zed/settings.json"
   {
     "languages": {
       "TypeScript": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       },
       "TSX": {
         "language_servers": [
           "typescript-ls",
           "!vtsls",
           "!typescript-language-server",
           "..."
         ]
       }
     },
     "lsp": {
       "typescript-ls": {
         // the extension's own download is TypeScript 7.0, which has no content mappers
         "binary": {
           "path": "node_modules/typescript/bin/tsc",
           "arguments": ["--lsp", "--stdio"]
         },
         "initialization_options": { "runExternalCode": true }
       }
     }
   }
   ```

3. Trust the folder. In restricted mode, Zed starts no language server.

Zed doesn't send `.sql` files to the language server, so an error inside one shows only in the type check.

### Skill

Install Reylo's agent skill, which gives your coding agent Reylo's rules for writing and running queries in every session:

```sh
npx skills add colinhacks/reylo --skill using-reylo
```

### Playground [#local-playground]

Run the [playground](/play) on your own database:

```sh
npx reylo play
```

It opens at http://127.0.0.1:4983 with your project's tables. Edit a query, and the params, the return type and the errors Reylo infers update as you type; nothing runs. Add `?q=` and a query to the address to open it with that query.

With no database URL, it starts PGlite (install `@electric-sql/pglite`) with your schema, or a directory of migrations applied in order:

```sh
npx reylo play --schema db/schema.sql
```

Scripts and agents get the same analysis as JSON, its params, return type, cardinality and errors:

```sh
curl "http://127.0.0.1:4983/api/analyze" --get --data-urlencode "q=select name from users where id = :id"
```
