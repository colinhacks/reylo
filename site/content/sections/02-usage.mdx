Write a query in a `.sql` file, import it, and run it with your database driver. The query is your database's own SQL: any function, operator or syntax it supports works. Reylo uses your live dev database to compile the query and retrieve its types.

```ts twoslash tab="main.ts" dialect="postgres"
import postgres from "postgres";
import getUser from "./get_user.sql";

const db = postgres(process.env.DATABASE_URL);
const user = await getUser.run(db, { id: 1 });
```

```sql tab="get_user.sql" dialect="all"
select id, name, email from users where id = :id::int
```

Pass your database client as the first argument of `.run()`: a pool, a client, or a connection or [transaction](#run) taken from one, from any of the [supported drivers](#run).

## `.sql`

To get the compiled query, with your database's own placeholders:

```ts
import getUser from "./get_user.sql";

getUser.sql; // "select id, name, email from users where id = $1::int"
```

To get the file's contents as written, before Reylo compiles its [parameters](/inference#naming), use `.raw`. Its path, relative to your project, is `.source`, a name for your [logs and traces](/observability); Reylo's own errors about the query start with it.

## `.run()`

To run an imported Reylo query, pass a database connection/pool into the `.run()` method along with any parameters:

```ts twoslash dialect="postgres"
import postgres from "postgres";
import getUser from "./get_user.sql";

const db = postgres(process.env.DATABASE_URL);

const user = await getUser.run(db, { id: 1 });
//    ^?
```

Reylo has no driver of its own: it runs each query on your app's database client, from any of these drivers. Each example also runs two queries in a transaction, a client of its own that you pass to `.run()` the same way. Await each query in turn, since a connection runs one statement at a time; on Postgres an error aborts the transaction, so every later statement in it fails until it rolls back ([Database errors](/postgres#database-errors)).

### Postgres [#postgres-drivers]

```ts twoslash tab="pg" dialect="postgres" tab-group="postgres-driver"
import pg from "pg";
import createUser from "./create_user.sql";
import getUser from "./get_user.sql";

const db = new pg.Pool({ connectionString: process.env.DATABASE_URL });

const user = await getUser.run(db, { id: 1 });

// two inserts in one transaction: both land, or neither
const client = await db.connect();
try {
  await client.query("begin");
  await createUser.run(client, { name: "Ada" });
  await createUser.run(client, { name: "Grace" });
  await client.query("commit");
} catch (error) {
  await client.query("rollback");
  throw error;
} finally {
  client.release();
}
```

## `.try()`

To get your database's errors as values, use `.try()`. It returns `{ value }`, or `{ error }` when the database refuses the query:

```ts twoslash tab="main.ts (Postgres)" dialect="postgres"
import createUser from "./create_user.sql";

const result = await createUser.try(db, {
  name: "Ada",
  email: "ada@example.com",
});
if (result.error?.condition === "unique_violation") {
  result.error.constraint;
  //           ^?
}
```

```ts twoslash tab="main.ts (MySQL)" dialect="mysql"
import createUser from "./create_user.sql";

const result = await createUser.try(db, {
  name: "Ada",
  email: "ada@example.com",
});
if (result.error?.code === "ER_DUP_ENTRY") {
  result.error.key;
  //           ^?
}
```

```ts twoslash tab="main.ts (SQLite)" dialect="sqlite"
import createUser from "./create_user.sql";

const result = await createUser.try(db, {
  name: "Ada",
  email: "ada@example.com",
});
if (result.error?.code === "SQLITE_CONSTRAINT_UNIQUE") {
  result.error.columns;
  //           ^?
}
```

```sql tab="create_user.sql" dialect="all"
insert into users (name, email) values (:name, :email)
```

The error is your database's own, typed with every code it defines, so TypeScript catches a misspelled one:

| Database | Its code | What else it names |
| --- | --- | --- |
| Postgres | `code`, the SQLSTATE, and `condition`, its name | `constraint`, `table`, `column`, `schema`, `detail`, `hint`, `position` |
| MySQL | `code`, the error's name, `errno` and `sqlState` | `key`, `constraint`, `table`, `column` |
| SQLite | `code`, the result code's name, and `errcode` | `table`, `columns`, `constraint` |

When the query runs none of your own code, such as a trigger or a function you wrote, Reylo also narrows each error to the names it can carry: a unique violation names one of the unique keys of the tables the query writes, as in the examples above. Your database's page says what it narrows.

Each driver's error is read into the same fields, and the driver's own error is the `cause`. Any other error still throws, as from `.run()`: a refused connection, say. The file exports the error's type as `QueryError`. On a synchronous SQLite driver, `.trySync()` returns the result itself.

On Postgres, an error aborts the transaction it is in, even an error `.try()` returned: every later statement in it fails, and the transaction rolls back. MySQL and SQLite keep it open after most errors. The [Postgres page](/postgres#database-errors) shows how to carry on after an error.

## `.readOnly`

To tell whether a query writes nothing, read `.readOnly`. It is `true` only where Reylo finds nothing that could write, so it's safe to run the query again after a lost connection:

```ts twoslash
import getUser from "./get_user.sql";

getUser.readOnly;
//      ^?
```

A write is `false`, and so is a query that locks rows or may call a volatile function, directly or through a view, a policy or an operator. A function of your own counts by the volatility it declares.

## `.with()`

To bind the query to a client, call `.with()`. It returns a function that takes the parameters:

```ts twoslash
import getUser from "./get_user.sql";

const get = getUser.with(db);
const user = await get({ id: 1 });
```
