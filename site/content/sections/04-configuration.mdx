title: "Configuration"
---

Configure Reylo in a `.reylo.yaml` (or `.reylo.yml`) file beside `package.json`. Every key is optional:

```yaml title=".reylo.yaml"
# the dev database Reylo reads your schema from (the default)
direct_url: ${DATABASE_URL}
# the .env files Reylo reads (the default)
env: [.env.local, .env]
# a parameter whose type cannot be inferred is an error (the default)
allow_untyped_params: false
# a Postgres array column holds one dimension (the default)
allow_nested_arrays: false
# a comment naming each query's file, for your database's monitoring (the default)
sqlcommenter: true
# the directory of Reylo's files: schema.sql, the migrations and its cache (the default)
dir: reylo
```

The `package.json` it sits beside is the nearest one at or above the directory Reylo runs in, short of your home directory: one in the home directory itself is passed over, and `reylo migrate init` starts no project there.

## `direct_url`

The dev database Reylo reads your schema from. It defaults to `DATABASE_URL`, and its scheme names the dialect:

```sh title=".env" tab="Postgres" tab-group="dialect"
# or postgresql://
DATABASE_URL=postgres://localhost:5432/app
```

```sh title=".env" tab="MySQL" tab-group="dialect"
# or mariadb://
DATABASE_URL=mysql://root@localhost:3306/app
```

```sh title=".env" tab="SQLite" tab-group="dialect"
# or sqlite:; the path starts at package.json
DATABASE_URL=file:./app.db
```

Point it at a direct connection, not a pooler: describing a query through a pooler in transaction mode, such as PgBouncer's, can fail. You can interpolate other variables from your environment to construct a connection string.

```yaml title=".reylo.yaml"
# the default is ${DATABASE_URL}
direct_url: postgres://${DB_USER}:${DB_PASSWORD}@${DB_HOST}:5432/app
```

A variable can fall back, as in a shell, when it is unset or empty:

```yaml title=".reylo.yaml"
direct_url: ${BUILD_DATABASE_URL:-${DATABASE_URL}}
```

To keep a password out of every file, `$(…)` runs a command, such as a password manager's or a cloud's token command, and puts what it prints in its place. Reylo runs it once per editor session or build, and again when the database refuses the login, as when a token expires.

```yaml title=".reylo.yaml"
# or $(aws rds generate-db-auth-token …) for a short-lived token
direct_url: postgres://app:$(op read op://dev/db/password)@db:5432/app
```

A type check or a build reads this database, so in CI and on your host it needs your migrations applied. The database a query runs on is the client you pass to `.run()`, so the two can differ.

A script that runs against production is typed on your dev database, and its queries warn when the two differ in a way that breaks their types ([When the schema changes](/typescript#when-the-schema-changes)). To type it on the database it runs on:

```sh
DATABASE_URL="$PRODUCTION_URL" node --import reylo/register report.ts
```

### TLS

The type check reads TLS settings from the URL in `direct_url`:

```sh title=".env"
# postgres: encrypted, no certificate check
DATABASE_URL=postgres://…/app?sslmode=require
# postgres: the certificate and host checked
DATABASE_URL=postgres://…/app?sslmode=verify-full
# mysql: encrypted, no certificate check
DATABASE_URL=mysql://…/app?ssl-mode=REQUIRED
# mysql: the certificate and host checked
DATABASE_URL=mysql://…/app?ssl-mode=VERIFY_IDENTITY
```

- With no setting, a Postgres connection is encrypted where the server offers it, and a MySQL connection isn't.
- Postgres also reads `sslrootcert`, `sslcert`, `sslkey` and `channel_binding`, as libpq does, and node-postgres's `ssl=true`.
- MySQL also reads mysql2's `ssl` setting, as JSON with `rejectUnauthorized`, `ca`, `cert` and `key`, and Prisma's `sslaccept=strict`.
- A certificate is also checked against the certificates `NODE_EXTRA_CA_CERTS` names, as Node checks it.

## `env`

The `.env` files Reylo reads, relative to `.reylo.yaml`. The first file that sets a variable wins, and the environment wins over every file.

```yaml title=".reylo.yaml"
# the default is [.env.local, .env]
env: [.env.development, .env]
```

Reylo reads them as `dotenv` does. A `#` outside quotes starts a comment, so quote a value that holds one:

```sh title=".env"
DATABASE_URL="postgres://app:pa#ss@localhost:5432/app" # the dev database
```

## `allow_untyped_params`

Whether a [parameter whose type cannot be inferred](/inference#a-parameter-nothing-types) may stay `unknown`.

By default it's an error that says to [cast it](/inference#casts).

```yaml title=".reylo.yaml"
# the default is false
allow_untyped_params: true
```

## `allow_nested_arrays`

Whether a Postgres array column may hold nested arrays.

Postgres doesn't track an array's dimensions, so by default Reylo types an array column with one, and `.run()` throws on a value of more. With this set, the column is typed at any depth, as `NestedArray<T>`, and nothing is refused.

```yaml title=".reylo.yaml"
# the default is false
allow_nested_arrays: true
```

## `sqlcommenter`

Each query Reylo sends ends with a comment that names its file, in [sqlcommenter](https://google.github.io/sqlcommenter/)'s format, so database monitoring that reads it, such as Datadog's and PlanetScale's, groups your queries by file. On SQLite the comment opens the query instead, since SQLite would write it into the name of a last column with no alias. The query's [`.sql`](/typescript#sql) leaves it out. Set `sqlcommenter: false` to leave it off what Reylo sends too.

```yaml title=".reylo.yaml"
# the default is true
sqlcommenter: false
```

```sql title="What Postgres receives for queries/get_user.sql, by default"
select id, name, email from users where id = $1::int /*file='queries%2Fget_user.sql'*/
```

## `dir`

The directory beside `.reylo.yaml` that holds Reylo's files: the `schema.sql`, `migrations/` and `reylo-lock.yaml` of [migrations](/migrations), which you commit, and its cache in `.cache/`, which keeps itself out of git.

```yaml title=".reylo.yaml"
# the default is reylo
dir: db
```

## `shadow_url`

The server where [migrations](/migrations) build their shadow databases, for a database whose own server refuses `create database`:

```yaml title=".reylo.yaml"
# the default is the database's own server
shadow_url: ${SHADOW_URL}
```

## `js.codecs`

The TypeScript type `.run()` gives a family of values, and that its parameters take. A family you leave out keeps [its default](/inference#primitives):

```yaml title=".reylo.yaml"
js:
  codecs:
    decimal: decimal.js  # or bignumber.js, big.js, number, or string (the default)
    bytes: string  # base64, or Uint8Array (the default)
    date: Temporal.PlainDate  # or string (the default)
    time: Temporal.PlainTime  # or string (the default)
    datetime: Temporal.PlainDateTime  # or string (the default)
    instant: Temporal.Instant  # or string (the default)
    duration: Temporal.Duration  # or string (the default)
    set: Array  # or Set (the default)
    vector: TypedArray  # or number[] (the default)
    geometry: GeoJSON  # or the database's encoding (the default)
    inet: ip-address  # or string (the default)
```

| Family | Postgres | MySQL | SQLite |
| --- | --- | --- | --- |
| `decimal` | `numeric` | `DECIMAL` | |
| `bytes` | `bytea` | `BINARY`, `VARBINARY`, `BLOB` | `BLOB` |
| `date` | `date` | `DATE` | a column declared `DATE` |
| `time` | `time` | | a column declared `TIME` |
| `datetime` | `timestamp` | `DATETIME`, `TIMESTAMP` | a column declared `DATETIME` or `TIMESTAMP` |
| `instant` | `timestamptz` | | |
| `duration` | `interval` | `TIME` | |
| `set` | | `SET` | |
| `vector` | pgvector's `vector`, `halfvec` | `VECTOR` | |
| `geometry` | PostGIS's `geometry`, `geography` | `GEOMETRY` | |
| `inet` | `inet`, `cidr` | | |

- Every codec is exact. A number refuses a decimal a double cannot hold, and a Temporal class refuses a value it has no form for, such as Postgres's `infinity` or an interval of one month less a day, so the error names the column instead of returning a wrong value.
- A parameter takes the codec's type: a `Temporal.Instant` where the column is an `instant`, so a row goes back in as it came out.
- A decimal library, named by its package, makes each decimal a value of its class, from your own install of it beside the `.sql` file. For big.js, also install `@types/big.js`. Since big.js has no `NaN` or infinity, it refuses a `numeric` that holds one.
- A decimal library rounds its own arithmetic as you set it: decimal.js rounds to 20 significant digits unless you raise its `precision`.
- A vector is a `Float32Array`, or a `Float16Array` for a `halfvec`, which needs TypeScript's `es2025` lib. Sent as JSON, a typed array is an object of its indexes, so spread it into an array first.
- A geometry is a GeoJSON geometry with its SRID as `srid`, typed by `@types/geojson`, which you install. A parameter without an `srid` takes the column's. GeoJSON has no M coordinates or curves, so a geometry with either is refused.
- A network address is an `Address4` or `Address6` from your own install of ip-address. Sent as JSON, one is an object of its fields, so send its `.address`.
- A codec reaches every value Reylo decodes: an array's elements, a Postgres row value's fields, and the members of a structured parameter. A value inside JSON the query builds keeps its JSON type.
- A 64-bit integer is always a `bigint`, its one exact type. Cast it in the query where you want a `number` or text, as `count(*)::int`.
- A Temporal codec needs a runtime with a global `Temporal`, and TypeScript's `esnext` lib.
