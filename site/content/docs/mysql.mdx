<p className="dk-subheader">How Reylo types queries on MySQL</p>

[Reylo](/) lets you import `.sql` files into TypeScript, with every query typed from your live database. This page covers how it types and runs queries on MySQL: column types, null values, row counts, parameters and drivers.

| | |
| --- | --- |
| MySQL versions | 8.0.22 or later; tested on 8.0, 8.4, 9.7 and 26.7 |
| Connection | A `mysql://` URL in `DATABASE_URL` or [`direct_url`](/#direct_url) |
| Drivers | `mysql2`, PlanetScale and `Bun.sql`, and Drizzle over `mysql2` ([Drivers](#drivers)) |
| Type checking | Needs `mysql2` in your project, to read the schema |

<Details summary="View the schema behind the examples" id="schema">

```sql file="schema.sql" dialect="mysql"
create table users (
  id int auto_increment primary key,
  name varchar(100) not null,
  email varchar(255) unique,
  role enum('admin', 'member') not null default 'member',
  active boolean not null default true,
  created_at datetime(3) not null default (utc_timestamp(3))
);
```

```sql file="schema.sql" dialect="mysql"
create table orders (
  id bigint auto_increment primary key,
  user_id int not null,
  total decimal(12, 2) not null,
  placed_at datetime(6) not null default (utc_timestamp(6)),
  ships_on date,
  receipt blob,
  foreign key (user_id) references users (id)
);
```

```sql file="schema.sql" dialect="mysql"
create table events (
  id int auto_increment primary key,
  kind varchar(10) not null,
  payload json not null check (json_schema_valid('{
    "type": "object",
    "properties": {
      "x": { "type": "integer" },
      "code": { "type": "string" }
    },
    "required": ["x"]
  }', payload))
);
```

</Details>

## Data types

Each MySQL type maps to one TypeScript type, and `.run()` returns the same value for it on every driver:

| SQL type | TypeScript | The value `.run()` returns |
| --- | --- | --- |
| `TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`, `YEAR` | `number` | `2026` |
| `BIGINT`, `BIGINT UNSIGNED`, `COUNT(*)` | `bigint` | `9007199254740993n` |
| `BOOLEAN` (a `TINYINT(1)`), `BIT(1)` | `boolean` | `true` |
| A comparison, `IS NULL`, `IN`, `BETWEEN`, `LIKE`, `EXISTS`, `NOT`, `AND`, `OR` | `boolean` | `false` |
| `DECIMAL`, `SUM(…)`, `AVG(…)`, `/` | `string` | `"12.50"` |
| `FLOAT`, `DOUBLE` | `number` | `1.1` |
| `CHAR`, `VARCHAR`, `TEXT` | `string` | `"Ada"` |
| `ENUM` | `string`, not a union of its labels | `"member"` |
| `SET` | `string` | `"a,c"` |
| `DATE` | `string` | `"2026-10-20"` |
| `DATETIME`, `TIMESTAMP` | `string` | `"2026-10-20T10:00:00.123"` |
| `TIME` | `string` | `"10:00:00"` |
| `JSON` | `unknown` | `{ a: 1 }` |
| `JSON` a JSON Schema `CHECK` holds | what the schema admits | `{ x: 10 }` |
| `json_object(…)`, `json_arrayagg(…)` | the object or array it builds | `{ total: 12.5 }` |
| `BINARY`, `VARBINARY`, `BLOB`, `BIT` wider than 1 | `Uint8Array` | `Uint8Array.of(1, 2, 255)` |
| `GEOMETRY` | `unknown` | its bytes, a `Uint8Array` |
| `VECTOR` | `number[]` | `[1, 2.5, -3]` |

Each example below pairs a SQL value with the value `.run()` returns for it: `select <SQL> as v` returns the row `{ v: <JavaScript> }`.

### Integers

A `BIGINT`, signed or unsigned, comes back as a JavaScript `bigint`. So do `COUNT(*)` and most integer expressions, such as `id + 1` and `length(name)`, since MySQL computes them as `BIGINT`. To get a `number`, cast to `double`:

```ts twoslash tab="main.ts"
import countOrders from "./my_count_orders.sql";

const counts = await countOrders.run(db);
//    ^?
```

```sql tab="my_count_orders.sql" dialect="mysql"
select count(*) as total, cast(count(*) as double) as total_number
from orders
```

When an expression's type depends on the value you pass, it's typed as every type it could be. For example, `:n + 1` is `bigint | number | string`, since MySQL may compute it as a `BIGINT`, a `DOUBLE` or a `DECIMAL`.

<Pairs>

- `CAST(1 AS SIGNED) + 1` → `2n`
- `CAST(1.5 AS DOUBLE) + 1` → `2.5`
- `CAST(1.5 AS DECIMAL(2,1)) + 1` → `"2.5"`

</Pairs>

### Decimals

A `DECIMAL` comes back as its exact text, keeping the column's scale. So do `SUM(…)`, `AVG(…)` and division, since MySQL computes them as `DECIMAL`: `sum(total)` returns `"19.75"`, and `id / 2` returns `"0.5000"`.

A `FLOAT` is a 32-bit float. On `mysql2` it comes back as its exact value; PlanetScale, and `Bun.sql` in a query without parameters, round it to its shorter text, `1.1`. A `DOUBLE` is the same on every driver.

<Pairs>

- `CAST(1.1 AS FLOAT)` → `1.100000023841858`
- `CAST(1.1 AS DOUBLE)` → `1.1`

</Pairs>

### Dates and times

No value comes back as a `Date`. Each is the text MySQL writes, with a `T` between the date and the time, and as many fraction digits as the column keeps:

```ts twoslash tab="main.ts"
import orderDates from "./my_order_dates.sql";

const order = await orderDates.run(db, { id: 1 });
//    ^?
```

```sql tab="my_order_dates.sql" dialect="mysql"
select placed_at, ships_on from orders where id = :id
```

If your runtime has `Temporal`, read the value with `Temporal.PlainDateTime.from()`.

<Rules>

**Fractions of a second**

A value has as many fraction digits as its type: a `DATETIME(3)` always has three, even when they're zero, and a `DATETIME` has none.

<Pairs>

- `CAST('2026-10-20 10:00:00.123456' AS DATETIME(6))` → `"2026-10-20T10:00:00.123456"`
- `CAST('2026-10-20 10:00:00' AS DATETIME(3))` → `"2026-10-20T10:00:00.000"`
- `CAST('2026-10-20 10:00:00' AS DATETIME)` → `"2026-10-20T10:00:00"`

</Pairs>

**A `TIMESTAMP`'s zone**

MySQL returns a `TIMESTAMP` in the session's `time_zone`, which Reylo can't know, so the text has no zone. To read UTC, run `set time_zone = '+00:00'` on the connection, or store UTC in a `DATETIME` with `utc_timestamp()`, as the schema above does.

</Rules>

### Truth values

MySQL has no boolean type: a `BOOLEAN` column is a `TINYINT(1)`, and a comparison returns 1 or 0. Reylo types `TINYINT(1)` and `BIT(1)` columns as `boolean`, and every comparison your query makes:

```ts twoslash tab="main.ts"
import userFlags from "./my_user_flags.sql";

const rows = await userFlags.run(db);
//    ^?
```

```sql tab="my_user_flags.sql" dialect="mysql"
select id, active, role = 'admin' as is_admin from users
```

<Rules>

**What counts**

These are typed `boolean`: comparisons, `IS`, `IN`, `BETWEEN`, `LIKE`, `REGEXP`, `EXISTS`, `NOT`, `AND`, `OR`, `XOR`, `TRUE` and `FALSE`, and a `CASE`, `IF`, `COALESCE`, `IFNULL`, `NULLIF` or subquery whose every value is one of them.

<Pairs>

- `'Ada' LIKE 'B%'` → `false`
- `IF(1 = 1, TRUE, FALSE)` → `true`

</Pairs>

**Where MySQL hides the column**

A boolean column stays `boolean` through a subquery in `from` or a `with` query. It becomes a number where MySQL hides the column: through a view, in `max(active)` or `active + 0`, and in a comparison made inside a subquery.

<Pairs>

- `TRUE + 0` → `1n`
- `max(1 = 1)` → `1n`
- `(SELECT b FROM (SELECT 1 = 1 AS b) d)` → `1n`

</Pairs>

**Values other than 0 and 1**

A `TINYINT(1)` can hold any number from −128 to 127. Reylo reads 0 and 1 as `false` and `true`, and throws an error naming the column for any other value. Store only 0 or 1, or read the number with `active + 0`.

</Rules>

### JSON

A `JSON` column is typed `unknown`, unless a `JSON_SCHEMA_VALID` `CHECK` constrains it and your query selects it straight from its table, or your query builds the JSON:

```ts twoslash tab="main.ts"
import events from "./my_events.sql";

const rows = await events.run(db);
//    ^?
```

```sql tab="my_events.sql" dialect="mysql"
select kind, payload from events
```

JSON your query builds with `json_object` and `json_arrayagg` is typed from what you put in it:

```ts twoslash tab="main.ts"
import orderSummaries from "./my_order_summaries.sql";

const rows = await orderSummaries.run(db);
//    ^?
```

```sql tab="my_order_summaries.sql" dialect="mysql"
select u.name,
  json_object('total', o.total, 'placed_at', o.placed_at) as summary
from orders o
join users u on u.id = o.user_id
```

A schema's type carries through `json_arrayagg`:

```ts twoslash tab="main.ts"
import eventsByKind from "./my_events_by_kind.sql";

const groups = await eventsByKind.run(db);
//    ^?
```

```sql tab="my_events_by_kind.sql" dialect="mysql"
select kind, json_arrayagg(payload) as payloads
from events
group by kind
```

<Rules>

**Values inside a document**

Inside JSON, a value can differ from the same value in a column. Numbers past 2^53 lose precision in `JSON.parse`, a `DATETIME` is MySQL's text, and a boolean may be `true` or `1`, depending on how MySQL writes it.

<Pairs>

- `CAST('{"n": 9007199254740993}' AS JSON)` → `{ n: 9007199254740992 }`
- `json_object('at', CAST('2026-10-20 10:00:00' AS DATETIME))` → `{ at: "2026-10-20 10:00:00.000000" }`
- `json_object('b', 1 = 1)` → `{ b: true }`
- `json_object('b', max(1 = 1))` → `{ b: 1 }`

</Pairs>

</Rules>

- **Where a schema's type applies:** selecting the column from a table named without a schema, and the column inside `json_object` or `json_arrayagg`.
- **Where it doesn't:** through a subquery or a `with` query, under a `union`, in an expression (`json_extract(payload, '$.x')`), and in a parameter written to the column, it's `unknown`.
- **Draft 4 only:** MySQL validates every schema as draft 4, whatever its `$schema` says, so `const`, `if`, `prefixItems` and `contains` don't narrow the type.
- **An empty array as a default,** as in `coalesce(json_arrayagg(…), json_array())`, keeps the array's type.

### Vectors

A `VECTOR`, new in MySQL 9, comes back as a `number[]` of 32-bit floats. A vector parameter takes a `number[]`, which works anywhere MySQL accepts a `VECTOR`; `NaN` and infinities are rejected before the query runs.

<Pairs>

- `STRING_TO_VECTOR('[1, 2.5, 0.1]')` → `[1, 2.5, 0.10000000149011612]`

</Pairs>

## Nullability

Every column is typed `| null` unless Reylo can tell it never is null. On MySQL, it starts from what the server reports for each column, then adds what the query's `where` and `group by` rule out.

- **A table's column** is non-null if it's `NOT NULL`.
- **An outer join** makes the joined table's columns nullable, unless a test that fails on `NULL` shows the joined row exists: `where p.published_at is not null` or `where p.id > 0` in the `where`, or a later inner join's `on`.
- **An expression** is non-null when the server says so: `coalesce` and `ifnull` with a non-null argument, `count`, `length`, arithmetic on non-null integers, and comparisons.
  - The server is cautious with string and date functions, most casts and division: `upper(name)`, `concat(name, '!')`, `date(created_at)`, `cast(id as char)` and `id / 2` are nullable even over a `NOT NULL` column.
- **A `where` test that fails on `NULL`** makes the column it tests non-null: `where email is not null`, `where email like '%@%'`, `where lower(email) = :email`. It doesn't count under an `or` that tests another column, or through `coalesce`, `ifnull` and `<=>`.
- **`json_arrayagg`** returns `NULL` over no rows, but is non-null with a `group by`, since every group has rows.
- **`WITH ROLLUP`** adds summary rows whose grouped columns are `NULL`, and the types include `null`.

A `where` test on the joined table means its row exists, so its columns are non-null:

```ts twoslash tab="main.ts"
import shipped from "./my_shipped.sql";

const rows = await shipped.run(db);
//    ^?
```

```sql tab="my_shipped.sql" dialect="mysql"
select u.name, o.total, o.ships_on
from users u
left join orders o on o.user_id = u.id
where o.ships_on is not null
```

To tell Reylo a value is never null, give it a default with `coalesce` or `ifnull`:

```ts twoslash tab="main.ts"
import shouts from "./my_shouts.sql";

const rows = await shouts.run(db);
//    ^?
```

```sql tab="my_shouts.sql" dialect="mysql"
select upper(name) as shout, coalesce(upper(name), '') as shout_or_empty
from users
```

## Cardinality

Reylo infers how many rows a query returns, and types `.run()`'s result to match:

| `.run()` returns | `cardinality` | When the query |
| --- | --- | --- |
| `Row` | `one` | is an aggregate without a `group by`, or `values row(…)` of one row |
| `Row \| null` | `maybeOne` | matches every column of one table's primary key or unique key with `=`, against a value of the key's own type; or has `limit 1` |
| `void` | `none` | is an `insert`, `update`, `delete` or `replace`, `on duplicate key update` included |
| `Row[]` | `many` | is anything else |

MySQL has no `returning`, so a write returns nothing. To read a new row's id, select `last_insert_id()` on the same connection:

```ts twoslash tab="main.ts"
import mysql from "mysql2/promise";
import lastInsertId from "./my_last_insert_id.sql";

const db = mysql.createPool(process.env.DATABASE_URL);
const conn = await db.getConnection();
// … run an insert on conn, then:
const { id } = await lastInsertId.run(conn);
//      ^?
conn.release();
```

```sql tab="my_last_insert_id.sql" dialect="mysql"
select last_insert_id() as id
```

These don't count as a key match, so the query returns `Row[]`:

- A joined table's key: `posts join users on users.id = posts.user_id where posts.id = :id`.
- A `distinct` or `group by`, unless it's over the key.
- A string key compared with a number, which MySQL compares as doubles: `where email = 5`.
- A `TIMESTAMP` key, since two instants can show as the same time when the clocks go back.
- A `WITH ROLLUP`, which adds rows, and a `with` query named like a table.

A multi-table `delete` or `update` returns nothing, and so does `select … into @variable`.

## Parameters

### Placeholders

Write parameters as `:name`, and pass `.run()` an object with those names. You can use MySQL's `?` instead, but not both in one query; then `.run()` takes an object keyed by number, `{ 1: 42 }`.

### What a parameter takes

A parameter accepts the same values `.run()` returns for its type, so you can pass a row straight into the next query:

| SQL type | A parameter takes |
| --- | --- |
| `TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`, `YEAR` | `number` |
| A `BIGINT` column | `number`, `bigint` or a string of digits |
| A `TINYINT(1)` or `BIT(1)` column | `boolean` or `number` |
| `DECIMAL` | `string` |
| `FLOAT`, `DOUBLE` | `number` |
| `CHAR`, `VARCHAR`, `TEXT`, `ENUM`, `SET` | `string` |
| `DATE`, `DATETIME`, `TIMESTAMP`, `TIME` | `string` |
| `JSON` | any JSON value |
| `BINARY`, `VARBINARY`, `BLOB` | `Uint8Array` |
| `VECTOR` | `number[]` |

- MySQL reports every integer parameter as a `BIGINT`, so Reylo types it from the column it's compared with (`col = :p`, `in`, `between`) or written to (an `insert` or `update`). Elsewhere it uses what MySQL reports: `limit :n` takes a `number`.
- A `DATE`, `DATETIME` or `TIMESTAMP` parameter takes the text, `"2026-10-12 19:06:48"`, and rejects a `Date`, since drivers convert a `Date` using different time zones.
- A `BINARY`, `VARBINARY` or `BLOB` parameter takes only a `Uint8Array`, and rejects base64 or hex text before the query runs, since MySQL would store the text's own bytes. Decode the text into a `Uint8Array` first.
- A JSON parameter is sent as JSON, so a string is stored as a JSON string: `'{"a":1}'` becomes `"{\"a\":1}"`.

### Parameters that may be null

A parameter accepts `null` in two places:

- as the first argument of `coalesce` or `ifnull`;
- written directly into a nullable column, with no cast, in an `insert`, `update`, `replace` or `on duplicate key update`. A column is nullable unless it's `NOT NULL` or a `check (… is not null)` covers it.

```ts twoslash tab="main.ts"
import addOrder, { type Params } from "./my_add_order.sql";
//                      ^?
```

```sql tab="my_add_order.sql" dialect="mysql"
insert into orders (user_id, total, ships_on)
values (:user_id, :total, :ships_on)
```

A cast sets the parameter's whole type, so `:email::text` never accepts `null`. Testing a parameter for null (`:p is null`, `:p <=> col`) doesn't make it nullable.

### Casts

MySQL has no `::` casts, so Reylo turns `:p::type` into MySQL's `CAST`. It also checks your value against the type before the query runs, since MySQL's `CAST` silently turns a bad value into 0 or `NULL`. MySQL's own `cast(:p as …)` works too.

| You write | MySQL runs |
| --- | --- |
| `::int`, `::bigint`, `::smallint` | `CAST(? AS SIGNED)` |
| `::int unsigned` | `CAST(? AS UNSIGNED)` |
| `::numeric(10,2)`, `::decimal(10,2)` | `CAST(? AS DECIMAL(10,2))` |
| `::real`, `::double precision` | `CAST(? AS FLOAT)`, `CAST(? AS DOUBLE)` |
| `::text`, `::varchar(20)`, `::uuid` | `CAST(? AS CHAR)`, `CAST(? AS CHAR(20))`, `CAST(? AS CHAR(36))` |
| `::date`, `::time`, `::datetime` | `CAST(? AS DATE)`, `CAST(? AS TIME)`, `CAST(? AS DATETIME(6))` |
| `::json` | `CAST(? AS JSON)` |
| `::bytea`, `::blob` | `CAST(? AS BINARY)` |

- The check rejects an integer out of range, a decimal with more digits than its scale, and a date that doesn't exist (`"2026-02-30"`).
- In `limit` and `offset`, which MySQL only allows as a bare `?`, write `:n::int`; any other cast there is an error.
- Casting to `::timestamptz` or `::boolean` is an error, since MySQL has neither type.

## Drivers

Reylo decodes its query results itself, so options you set on your client don't affect Reylo's queries, and Reylo's don't affect yours. Drivers differ only in what they reject or lose:

| Driver | Not supported | Lost before Reylo sees it |
| --- | --- | --- |
| `mysql2` | | |
| PlanetScale | Version 2.0, which can't bind parameters | |
| `Bun.sql` | | Microseconds of a `DATETIME`, a fraction that is all zeros, and a `TIME`'s fraction in a query with parameters |

- On `Bun.sql`, an expression that could be a `BIGINT` or a `DECIMAL` (`round(:x)`) comes back as a `bigint` when it has no decimal point, since Bun returns both as text. Bun 1.4 can't read a `VECTOR` at all (`ERR_MYSQL_UNSUPPORTED_COLUMN_TYPE`), so select `vector_to_string(v)` instead.
- Transactions and connections from each driver work too: `mysql2`'s promise and callback APIs, PlanetScale's `.transaction()`, `Bun.sql`'s `.begin()`, `.savepoint()` and `.reserve()`, and a Drizzle database's `.transaction()` and savepoints, over `mysql2`.

Type checking reads your schema through `mysql2`, so if your app uses PlanetScale or `Bun.sql`, add `mysql2` as a dev dependency.

## Limits

What Reylo can't type on MySQL, and what to write instead:

- **`ENUM` labels.** An `ENUM` is typed `string`, not the union of its labels. Check the value in TypeScript where you need the union.
- **Error positions.** MySQL doesn't say where in a query an error is, so the type check marks the whole query.
- **Queries Reylo can't parse.** Reylo parses each query to infer row counts and JSON shapes. If it can't, the query keeps MySQL's types and nullability, returns `Row[]`, and any JSON is `unknown`.
- **Non-default `sql_mode`.** If your session's `sql_mode` changes how MySQL reads a query (`NO_BACKSLASH_ESCAPES`, `ANSI_QUOTES`, `PIPES_AS_CONCAT`), Reylo keeps MySQL's types and infers no row counts or JSON shapes.
- **`/*! … */` comments.** MySQL runs the SQL inside them, so a query with one is an error. Write it as plain SQL.
- **`with` before `insert`.** MySQL 8.4 rejects `with … insert`, so put the `with` after `insert into … (…)`, as in [JSON parameters](/#typed-json).
- **Very large queries.** Past 500 operators (`a + b + …`, `x = 1 or x = 2 or …`), or 200 levels of nesting, Reylo uses only what MySQL reports: any number of rows.
