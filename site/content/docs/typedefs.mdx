A format for types.

Reylo writes the type of every parameter and column it [analyzes](/analyze) in it. A type says which values a position can hold, precisely enough to pick a representation in any language that holds them all.

## Types

Each type is an object with a `kind`.

The other fields narrow the kind: a size, bounds, a pattern, the values it may take. A program reads `kind` and the fields it needs, and ignores the rest, since a field it doesn't know can only narrow. A few fields widen a type instead, each named under its kind below.

```jsonc
// A 32-bit integer from 0 to 150, which Postgres calls int4
{ "kind": "integer", "bits": 32, "min": "0", "max": "150", "label": "int4" }
```

- **Values inside a type are strings**, in the kind's canonical text, so a 64-bit bound or a date survives any encoding. Counts, such as `bits`, are numbers.
- **A flag appears only when it's true.** Its absence means false.
- **A label is the database's name** for the type, where it has one. It never changes what the type means.
- **A comment** is the documentation the source keeps on a named type.

### Positions

Where a value stands, with whether it may be null.

A column, a parameter, a record's field, an array's element and a map's value are each a position: a `type`, and `nullable` where the value may be null. Nullability is on the position and never in the type, since an outer join makes any column nullable.

```jsonc
// Text that may be null
{ "type": { "kind": "text" }, "nullable": true }
```

### Literals

A type of one value.

A kind that lists its values in `enum` holds only those, and one value makes a literal. Every value is in the kind's canonical text, so a literal keeps its type: the integer 1 and the text `"1"` are two literals.

```jsonc
// The integer 1
{ "kind": "integer", "bits": 32, "enum": ["1"] }

// The literal true
{ "kind": "boolean", "enum": ["true"] }

// One of two strings
{ "kind": "text", "enum": ["admin", "member"] }
```

## Kinds

Every type has one of these kinds:

| Kind | What it holds |
| --- | --- |
| [`boolean`](#boolean) | A truth value |
| [`integer`](#integer) | A whole number of a fixed width |
| [`float`](#float) | An IEEE 754 binary float |
| [`decimal`](#decimal) | An exact decimal |
| [`text`](#text) | Text |
| [`bytes`](#bytes) | Bytes |
| [`uuid`](#uuid) | A 128-bit identifier |
| [`array`](#array) | Elements in order, rows among them |
| [`record`](#record) | Named fields |
| [`tuple`](#tuple) | Values in order, with no names |
| [`json`](#json) | A JSON value |
| [`date`](#date) | A calendar date |
| [`time`](#time) | A time of day |
| [`datetime`](#datetime) | A date and time as a wall clock reads it |
| [`instant`](#instant) | A point on the timeline |
| [`duration`](#duration) | A length of time |
| [`union`](#union) | One of several types |
| [`tagged_union`](#tagged_union) | One of several alternatives, named by a tag |
| [`map`](#map) | Keys to values |
| [`range`](#range) | A range of an ordered type |
| [`multirange`](#multirange) | Non-overlapping ranges |
| [`geometry`](#geometry) | An OGC simple feature |
| [`xml`](#xml) | XML |
| [`opaque`](#opaque) | A type the format doesn't structure |
| [`unknown`](#unknown) | Nothing is known |

### `boolean`

A truth value.

A comparison's result is one on every database, though MySQL and SQLite deliver it as 1 or 0.

<TypeDef holds={["true", "false"]} types={{"postgres": ["boolean"], "duckdb": ["boolean"]}}>

```jsonc
// Any truth value
{ "kind": "boolean" }

// The literal true
{ "kind": "boolean", "enum": ["true"] }
```

</TypeDef>

### `integer`

A whole number of a fixed width.

Its range follows from `bits`, two's complement unless `unsigned`. A bound is always inclusive, since `x > 0` is `x >= 1`.

<TypeDef holds={["-2147483648", "0", "2147483647"]} types={{"postgres": ["smallint", "integer", "bigint", "oid"], "mysql": ["tinyint", "smallint", "mediumint", "int", "bigint", "year", "boolean"], "sqlite": ["integer"], "duckdb": ["tinyint", "smallint", "integer", "bigint", "hugeint", "utinyint", "usmallint", "uinteger", "ubigint", "uhugeint"]}}>

```jsonc
// A 32-bit integer
{ "kind": "integer", "bits": 32 }

// A 64-bit unsigned integer
{ "kind": "integer", "bits": 64, "unsigned": true }

// From 0 to 150, and a multiple of 5
{ "kind": "integer", "bits": 32, "min": "0", "max": "150", "multiple_of": "5" }
```

</TypeDef>

### `float`

An [IEEE 754](https://en.wikipedia.org/wiki/IEEE_754) binary float.

Its exponent and mantissa widths fix its range and precision, so a program picks the smallest float it has that holds both. It holds the infinities and NaN only where `infinity` and `nan` say so.

<TypeDef holds={["1.5", "-0", "Infinity", "NaN"]} types={{"postgres": ["real", "double precision"], "mysql": ["float", "double"], "sqlite": ["real"], "duckdb": ["float", "double"]}}>

```jsonc
// A double
{ "kind": "float", "exponent_bits": 11, "mantissa_bits": 52 }

// A double that also holds Infinity, -Infinity and NaN
{ "kind": "float", "exponent_bits": 11, "mantissa_bits": 52, "infinity": true, "nan": true }

// A single-precision float above 0
{ "kind": "float", "exponent_bits": 8, "mantissa_bits": 23, "exclusive_min": "0" }
```

</TypeDef>

### `decimal`

An exact decimal.

Its `precision` counts its digits, and its scale the digits after the point. A decimal is a number, so `1.5` and `1.50` are one value.

<TypeDef holds={["1.50", "99999999.99", "NaN"]} types={{"postgres": ["numeric"], "mysql": ["decimal"], "duckdb": ["decimal", "bignum"]}}>

```jsonc
// Up to 10 digits, 2 after the point
{ "kind": "decimal", "precision": 10, "min_scale": 2, "max_scale": 2 }

// Any decimal below 10^131072, NaN and the infinities too
{ "kind": "decimal", "min_scale": 0, "max_scale": 16383, "exclusive_min": "-1e131072", "exclusive_max": "1e131072", "infinity": true, "nan": true }
```

</TypeDef>

### `text`

Text.

Its size counts code points unless its `unit` says otherwise. A `pattern` is one every value matches, in the dialect it names.

<TypeDef holds={["\"ada@example.com\"", "\"happy\"", "\"\""]} types={{"postgres": ["text", "varchar", "char", "name", "an enum"], "mysql": ["char", "varchar", "tinytext", "text", "mediumtext", "longtext", "enum"], "sqlite": ["text"], "duckdb": ["varchar", "enum"]}}>

```jsonc
// At most 255 code points
{ "kind": "text", "size": { "max": 255 } }

// One of two values
{ "kind": "text", "enum": ["happy", "sad"] }

// Text that matches a LIKE pattern
{ "kind": "text", "pattern": { "dialect": "like", "source": "%@%" } }

// At most 65,535 bytes of UTF-8
{ "kind": "text", "size": { "unit": "byte", "encoding": "UTF-8", "max": 65535 } }

// Bytes meant as UTF-8 that nothing checked, which may not be valid Unicode
{ "kind": "text", "ill_formed": "utf8" }
```

</TypeDef>

### `bytes`

Bytes.

The type states their length where it fixes one.

<TypeDef holds={["0x0102", "0x"]} types={{"postgres": ["bytea", "macaddr", "macaddr8"], "mysql": ["binary", "varbinary", "tinyblob", "blob", "mediumblob", "longblob"], "sqlite": ["blob"], "duckdb": ["blob"]}}>

```jsonc
// Any number of bytes
{ "kind": "bytes" }

// Exactly 16 bytes
{ "kind": "bytes", "size": { "exact": 16 } }
```

</TypeDef>

### `uuid`

A 128-bit identifier.

It holds any 128 bits, written in [RFC 9562](https://www.rfc-editor.org/rfc/rfc9562)'s text form. A `version` says every value has that RFC 9562 version: a UUID that `uuidv7()` or `gen_random_uuid()` makes, or a column whose `CHECK`s hold `uuid_extract_version` to one and keep it non-null. A column with a `default uuidv7()` has none, since an insert may write any UUID.

<TypeDef holds={["019a6b2c-3d4e-7f80-9a1b-2c3d4e5f6071"]} types={{"postgres": ["uuid"], "duckdb": ["uuid"]}}>

```jsonc
// Any 128 bits
{ "kind": "uuid" }

// A version 7 UUID
{ "kind": "uuid", "version": 7 }
```

</TypeDef>

### `array`

Elements, in order.

Each element is a position of its own, so it says whether it may be null. A [pgvector](https://github.com/pgvector/pgvector) vector is an array of floats, and a Postgres array column takes `any_depth`, since Postgres doesn't enforce its dimensions.

- **A set** is an array whose elements never repeat, `distinct`, as MySQL's `SET` is.
- **Rows** are an array of records. Its `size` is how many rows, `unique` the sets of fields no two rows share, a table's primary key first, and `order` the fields the rows are sorted on.

<TypeDef holds={["[1, null, 3]", "[]"]} types={{"postgres": ["any array", "bit", "varbit", "lseg", "polygon", "vector", "halfvec"], "mysql": ["set", "bit"], "duckdb": ["list", "array", "bit"]}}>

```jsonc
// Integers, each of which may be null
{ "kind": "array", "element": { "type": { "kind": "integer", "bits": 32 }, "nullable": true } }

// Exactly 3 floats
{ "kind": "array", "size": { "exact": 3 }, "element": { "type": { "kind": "float", "exponent_bits": 8, "mantissa_bits": 23 } } }

// Members that never repeat
{ "kind": "array", "distinct": true, "element": { "type": { "kind": "text", "enum": ["a", "b", "c"] } } }

// Rows, unique by id, newest first
{
  "kind": "array",
  "unique": [["id"]],
  "order": [{ "field": "created_at", "desc": true, "nulls": "last" }],
  "element": {
    "type": {
      "kind": "record",
      "fields": [
        { "name": "id", "type": { "kind": "integer", "bits": 64 } },
        { "name": "created_at", "type": { "kind": "instant", "tick": "1/1000000" } }
      ]
    }
  }
}
```

</TypeDef>

### `record`

Named fields, in order.

Each field is a position with a `name`. It may be `optional`, its key left out, with a `default` the key takes when it is. A record holds exactly its fields, unless `extra` lets it hold other keys too.

<TypeDef holds={["{ \"x\": 1, \"y\": 2 }"]} types={{"postgres": ["a composite type", "point", "line", "box", "path", "circle"], "duckdb": ["struct"]}}>

```jsonc
// A point
{
  "kind": "record",
  "fields": [
    { "name": "x", "type": { "kind": "float", "exponent_bits": 11, "mantissa_bits": 52 } },
    { "name": "y", "type": { "kind": "float", "exponent_bits": 11, "mantissa_bits": 52 } }
  ]
}

// An optional field, with its default and its comment
{
  "kind": "record",
  "fields": [
    { "name": "id", "type": { "kind": "integer", "bits": 64 } },
    { "name": "role", "optional": true, "default": "member", "comment": "What the user may do", "type": { "kind": "text", "enum": ["admin", "member"] } }
  ]
}

// An open object, whose other keys hold text
{
  "kind": "record",
  "fields": [{ "name": "id", "type": { "kind": "integer", "bits": 64 } }],
  "extra": { "type": { "kind": "text" } }
}
```

</TypeDef>

### `tuple`

Values in order, each of its own type, with no names.

<TypeDef holds={["[1, \"a\"]", "[2, null]"]}>

```jsonc
// An integer, then text that may be null
{ "kind": "tuple", "elements": [{ "type": { "kind": "integer", "bits": 32 } }, { "type": { "kind": "text" }, "nullable": true }] }
```

</TypeDef>

### `json`

A [JSON](https://www.rfc-editor.org/rfc/rfc8259) value.

Its `content` is what a statement built, in these same types, and its `schema` a [JSON Schema](https://json-schema.org) every value satisfies. With neither, it's any JSON.

<TypeDef holds={["{ \"id\": 1, \"title\": \"Hello\" }", "null"]} types={{"postgres": ["json", "jsonb"], "mysql": ["json"], "duckdb": ["json"]}}>

```jsonc
// Any JSON value
{ "kind": "json" }

// An object of an id and a title
{
  "kind": "json",
  "content": {
    "type": {
      "kind": "record",
      "fields": [
        { "name": "id", "type": { "kind": "integer", "bits": 64 } },
        { "name": "title", "type": { "kind": "text" } }
      ]
    }
  }
}

// What a JSON Schema admits
{ "kind": "json", "schema": { "$schema": "https://json-schema.org/draft/2020-12/schema", "type": "object", "required": ["x"] } }
```

</TypeDef>

### `date`

A calendar date.

Its bounds are [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) text, with a sign and more than four digits where a year needs them. With no bounds, it runs from 0001-01-01 to 9999-12-31.

<TypeDef holds={["2026-11-04", "-infinity"]} types={{"postgres": ["date"], "mysql": ["date"], "duckdb": ["date"]}}>

```jsonc
// Any date from 0001 to 9999
{ "kind": "date" }

// From 4714 BC to the year 5874897, and infinity and -infinity too
{ "kind": "date", "min": "-4713-11-24", "max": "+5874897-12-31", "infinity": true }
```

</TypeDef>

### `time`

A time of day.

Its `tick` is its smallest step, in seconds. It holds 24:00:00 only where its bounds say so, and keeps a UTC offset where `zone` says so.

<TypeDef holds={["09:30:00", "24:00:00"]} types={{"postgres": ["time", "timetz"], "duckdb": ["time", "timetz", "time_ns"]}}>

```jsonc
// To the microsecond, up to 24:00:00
{ "kind": "time", "tick": "1/1000000", "max": "24:00:00" }

// To the second, with its UTC offset
{ "kind": "time", "tick": "1", "zone": "offset" }
```

</TypeDef>

### `datetime`

A date and time as a wall clock reads it.

With no zone, it can't be read as an instant.

<TypeDef holds={["2026-11-04T09:30:00.123"]} types={{"postgres": ["timestamp"], "mysql": ["datetime"], "duckdb": ["timestamp", "timestamp_s", "timestamp_ms", "timestamp_ns"]}}>

```jsonc
// To the millisecond
{ "kind": "datetime", "tick": "1/1000" }
```

</TypeDef>

### `instant`

A point on the timeline.

It's one moment however a session prints it. Its bounds are in UTC, and `zone` says what each value keeps besides the moment.

<TypeDef holds={["2026-11-04T17:30:00.123456Z"]} types={{"postgres": ["timestamptz"], "mysql": ["timestamp"], "duckdb": ["timestamptz"]}}>

```jsonc
// To the microsecond, and infinity and -infinity too
{ "kind": "instant", "tick": "1/1000000", "infinity": true }

// One that keeps its UTC offset
{ "kind": "instant", "tick": "1/10000000", "zone": "offset" }
```

</TypeDef>

### `duration`

A length of time.

Its parts are months, days and a time, each signed on its own, so 1 month and 30 days are two values. Its `max` is an [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) duration of the parts it has, each at the largest magnitude it reaches.

<TypeDef holds={["P1M3D", "PT1H30M", "P-2D"]} types={{"postgres": ["interval"], "mysql": ["time"], "duckdb": ["interval"]}}>

```jsonc
// Months, days and a time to the microsecond
{ "kind": "duration", "max": "P2147483648M2147483648DT2562047788H54.775808S", "tick": "1/1000000" }

// A time alone, up to 838 hours, to the second
{ "kind": "duration", "max": "PT838H59M59S", "tick": "1" }
```

</TypeDef>

### `union`

One of several types.

A union is flat, and lists its members in the order of the kinds. A union of records that each give one field a different literal is a discriminated union, as OpenAPI's discriminator and TypeScript describe one: each value says which member it is by that field.

<TypeDef holds={["12", "\"abc\""]} types={{"postgres": ["inet", "cidr"], "sqlite": ["any column outside a strict table"]}}>

```jsonc
// An integer or text
{ "kind": "union", "members": [{ "kind": "integer", "bits": 64 }, { "kind": "text" }] }

// A cat or a dog, which its type field names
{
  "kind": "union",
  "members": [
    { "kind": "record", "fields": [{ "name": "type", "type": { "kind": "text", "enum": ["cat"] } }, { "name": "meows", "type": { "kind": "boolean" } }] },
    { "kind": "record", "fields": [{ "name": "type", "type": { "kind": "text", "enum": ["dog"] } }, { "name": "barks", "type": { "kind": "boolean" } }] }
  ]
}

// No value at all: at a nullable position, always null
{ "kind": "union", "members": [] }
```

</TypeDef>

### `tagged_union`

One of several alternatives, each named by a tag.

Every value carries its tag beside the value, even where the value is null. Unlike a union's members, two alternatives may hold one type.

<TypeDef holds={["{ \"tag\": \"num\", \"value\": 1 }"]} types={{"duckdb": ["union"]}}>

```jsonc
// A number or text, each tagged
{
  "kind": "tagged_union",
  "alternatives": [
    { "tag": "num", "type": { "kind": "integer", "bits": 32 }, "nullable": true },
    { "tag": "str", "type": { "kind": "text" }, "nullable": true }
  ]
}
```

</TypeDef>

### `map`

Keys to values, each key once.

A key is never null. A map whose keys may repeat is an array of `{ key, value }` records.

<TypeDef holds={["{ \"color\": \"red\", \"size\": null }"]} types={{"postgres": ["hstore"], "duckdb": ["map"]}}>

```jsonc
// Text keys to text that may be null
{ "kind": "map", "key": { "kind": "text" }, "value": { "type": { "kind": "text" }, "nullable": true } }
```

</TypeDef>

### `range`

A range of an ordered type.

It may be empty, and either end may be unbounded.

<TypeDef holds={["[2026-11-04T09:00Z, 2026-11-04T10:00Z)", "empty"]} types={{"postgres": ["int4range", "int8range", "numrange", "tsrange", "tstzrange", "daterange"]}}>

```jsonc
// A range of instants
{ "kind": "range", "subtype": { "kind": "instant", "tick": "1/1000000" } }
```

</TypeDef>

### `multirange`

Non-overlapping ranges, in order.

<TypeDef holds={["{[1,3), [5,8)}", "{}"]} types={{"postgres": ["int4multirange", "int8multirange", "nummultirange", "tsmultirange", "tstzmultirange", "datemultirange"]}}>

```jsonc
// Ranges of integers
{ "kind": "multirange", "subtype": { "kind": "integer", "bits": 32 } }
```

</TypeDef>

### `geometry`

An [OGC simple feature](https://www.ogc.org/standards/sfa/).

It may name its model, its spatial reference, its subtype and its coordinates.

<TypeDef holds={["SRID=4326;POINT(-71.06 42.36)"]} types={{"postgres": ["geometry", "geography"], "mysql": ["geometry", "point", "linestring", "polygon", "multipoint", "multilinestring", "multipolygon", "geometrycollection"]}}>

```jsonc
// A point in WGS 84, with X and Y
{ "kind": "geometry", "srid": 4326, "subtype": "point", "coordinates": "xy" }

// Any shape on the sphere
{ "kind": "geometry", "model": "geodetic" }
```

</TypeDef>

### `xml`

[XML](https://www.w3.org/TR/xml/).

A document with one root, or with `fragment` several.

<TypeDef holds={["<a/>", "<a/><b/>"]} types={{"postgres": ["xml"]}}>

```jsonc
// A document
{ "kind": "xml" }

// A fragment, which may have several roots
{ "kind": "xml", "fragment": true }
```

</TypeDef>

### `opaque`

A type the format doesn't structure.

Its `label` is all the format says. A program that meets a kind it doesn't know reads it as this one.

<TypeDef holds={["top.science.physics"]} types={{"postgres": ["money", "tsvector", "tsquery", "pg_lsn", "an extension's type"]}}>

```jsonc
// A Postgres extension's type, known by its name
{ "kind": "opaque", "label": "ltree" }
```

</TypeDef>

### `unknown`

Nothing is known about the values.

A parameter nothing in the statement types is one, where [`allow_untyped_params`](/configuration#allow_untyped_params) lets it through.

<TypeDef types={{"sqlite": ["any column in a strict table"]}}>

```jsonc
// Any value
{ "kind": "unknown" }
```

</TypeDef>
