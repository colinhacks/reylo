Reylo writes one descriptor per query, the same for every database:

<TypeDef id="first" notes={{"$schema": "the format, and its version", "dialect": "every label below is this dialect's", "sql": "as the database runs it", "comment": "the comment before the statement", "result.cardinality": "one, at_most_one, many or none", "diagnostics": "errors, each at its place"}}>

```sql schema
create table users (
  id int8 primary key,
  email varchar(255) not null
)
```

```sql
-- One user's email
select email from users where id = :id::int8
```

</TypeDef>

## Usage

Analyze a statement to read its descriptor:

```ts
import { analyze } from "reylo";

const defs = await analyze({
  sql: "select email from users where id = :id::int8",
  url: "postgres://localhost/app",
});
```

Or analyze a file from the command line, which prints one descriptor per statement:

```sh
npx reylo analyze queries/get_user.sql
```

### `$schema`

The format's version, as the URL of its JSON Schema.

An editor or a validator reads the schema at that URL. Versions are [semantic](https://semver.org), and until 1.0.0 a new minor version may change anything.

<TypeDefPart of="first" show="$schema" />

### `dialect`

The database, and its server's version.

Every `label` in the descriptor is this database's name for a type.

<TypeDefPart of="first" show="dialect" />

### `sql`

The statement as the database runs it.

It has the database's own placeholders, `$1` on Postgres and `?` on MySQL and SQLite, in the order `params` lists them.

<TypeDefPart of="first" show="sql" />

### `kind`

What the statement does.

It is `select`, `insert`, `update`, `delete`, `merge`, or `other` for a `CALL`, an `EXPLAIN`, a `SHOW` or DDL, and absent when the statement does not parse.

<TypeDefPart of="first" show="kind" />

### `comment`

The prose in comments before the statement.

<TypeDefPart of="first" show="comment" />

### `params`

What the statement takes, in order.

Each has a `name` and a `type`, with `nullable` where it accepts null and `optional` where it may be left out.

<TypeDefPart of="first" show="params" />

### `result`

What the statement returns, as a [`rows`](#rows) type.

Each column has a `name` and a `type`, with `nullable` where it may be null. Nullability is on the column and never in its type, since an outer join makes any column nullable.

<TypeDefPart of="first" show="result" />

### `diagnostics`

What the database reports against the statement, each at its place.

Offsets count UTF-16 units of the statement as written, so an editor can underline it. A statement with a diagnostic has no columns.

<TypeDef show="diagnostics" errors>

```sql schema
create table users (
  id int8 primary key
)
```

```sql
select emial from users
```

</TypeDef>

## Kinds

Every type has a `kind`:

| Kind | What it holds | For example |
| --- | --- | --- |
| [`boolean`](#boolean) | A truth value | `boolean`, a comparison |
| [`integer`](#integer) | A whole number of a fixed width | `int4`, `BIGINT UNSIGNED` |
| [`float`](#float) | An IEEE 754 binary float | `float8`, `REAL` |
| [`decimal`](#decimal) | An exact decimal | `numeric(10,2)`, `DECIMAL` |
| [`text`](#text) | Text, with its size and values | `varchar(255)`, an enum |
| [`bytes`](#bytes) | Bytes | `bytea`, `BLOB` |
| [`uuid`](#uuid) | A 128-bit identifier | `uuid` |
| [`array`](#array) | A sequence of elements | `int4[]`, `vector(3)` |
| [`record`](#record) | Fields, in order | `point`, a composite |
| [`json`](#json) | A JSON value, and what it holds | `jsonb`, `JSON` |
| [`date`](#date) | A calendar date | `date` |
| [`time`](#time) | A time of day | `time(3)`, `timetz` |
| [`datetime`](#datetime) | A wall-clock date and time | `timestamp`, `DATETIME` |
| [`instant`](#instant) | A point on the timeline | `timestamptz` |
| [`duration`](#duration) | A length of time | `interval` |
| [`union`](#union) | One of several types | SQLite `NUMERIC` |
| [`set`](#set) | Elements in no order | MySQL `SET` |
| [`map`](#map) | Keys to values | `hstore` |
| [`range`](#range) | A range of an ordered type | `tstzrange` |
| [`multirange`](#multirange) | Non-overlapping ranges | `int4multirange` |
| [`geometry`](#geometry) | An OGC simple feature | PostGIS `geometry` |
| [`xml`](#xml) | XML | `xml` |
| [`opaque`](#opaque) | A type the format does not structure | `ltree`, `money` |
| [`unknown`](#unknown) | Nothing is known | an untyped parameter |
| [`tagged_union`](#tagged_union) | Alternatives named by a tag | DuckDB `UNION` |
| [`rows`](#rows) | Rows of columns | a statement's result |

A type is its `kind` and the fields that narrow it, so a program can read `kind` and ignore the fields it has no use for. Its `label` is the database's name for it, where it has one. A few fields widen a type instead, each named on its kind below, and a flag appears only when it is true. Bounds are strings in the kind's canonical text, so a 64-bit bound survives JSON.

### `integer`

A whole number of a fixed width.

Its range follows from the width, two's complement unless `unsigned`. A bound on one is always inclusive, since `x > 0` is `x >= 1`. MySQL's `BOOLEAN` is an integer, since it can hold 5.

### `json`

A [JSON](https://www.rfc-editor.org/rfc/rfc8259) value.

### `rows`

Rows of columns.

It is what every statement returns as its [`result`](#result), and a relation nested in a value is the same kind, as SQL's `MULTISET` and Oracle's nested tables are. Its `cardinality` is `one`, `at_most_one`, `many`, or `none` for a write without `returning`.

On rows that can be more than one, Postgres also writes:

- `unique`: each set of columns no two rows agree on, a table's primary key first where the rows hold it. A NULL counts as equal to another NULL.
- `order`: the columns the rows are sorted on, each with its direction and where its NULLs sort. It ends at the first `ORDER BY` key that isn't a column of the result, since a later key sorts only among rows that tie on that one.

<TypeDef show="result" notes={{"result.unique": "no two rows agree on any of these sets", "result.order": "email, highest first, then id"}}>

```sql schema
create table users (
  id int8 primary key,
  email varchar(255) not null unique
)
```

```sql
select id, email from users order by email desc, id
```

</TypeDef>
