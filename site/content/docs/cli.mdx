Every command and flag of `reylo`.

In a JavaScript project, run it with `npx reylo`. Elsewhere, install the binary on its own:

```bash tab="Homebrew"
brew install reylosql/tap/reylo
```

```bash tab="curl"
curl -fsSL https://reylo.dev/install.sh | sh
```

```powershell tab="PowerShell"
irm https://reylo.dev/install.ps1 | iex
```

```bash tab="Scoop"
scoop bucket add reylo https://github.com/reylosql/scoop-bucket
scoop install reylo
```

```bash tab="Docker"
docker run --rm -v "$PWD:/work" ghcr.io/reylosql/reylo migrate status
```

To pin a version, name it in mise's `mise.toml`. Every developer and CI job then installs it with `mise install`:

```toml title="mise.toml"
[tools]
"github:reylosql/reylo" = "0.8.0"
```

The scripts take `REYLO_VERSION=0.8.0`. The image takes a tag, as `ghcr.io/reylosql/reylo:0.8.0`.

Each command reads the database your project names, as the type check does:

```terminal
Usage: reylo <command> [flags]

Commands:
  analyze <paths>          Print what Reylo infers for each statement
    --sql <statement>      Read this statement, in place of files
    --url <url>            The database, in place of the project's
    --format <yaml|json>   YAML, the default, or a line of JSON per statement
  generate <generator>     Write each .sql file's module for a language
    --out <file>           Write every module into one file
  migrate <command>        Write, check and run your migrations
  db <command>             Push, reset, wipe or print a development database
  run <sql>                Run SQL as written, recording nothing
    --file <path>          Run a file's SQL too, after the text
    --url <url>            The database, in place of the project's
  play                     Serve the playground on this machine
    --port <n>             The port, 4983 by default
    --no-open              Leave the browser closed

Flags:
  -h, --help               Print this help
  --version                Print the version
```

## `reylo analyze`

Prints what Reylo infers for each statement ([Inference](/inference)):

```sh
reylo analyze src/queries
reylo analyze 'src/**/*.sql' --format json
reylo analyze --sql 'select id, email from users'
```

## `reylo generate`

Writes each `.sql` file's module for a language, as `#[reylo::query]` does for Rust. [Usage with Rust](/rust#codegen) covers it.

## `reylo migrate`

Write, check and run your migrations. [Reylo Migrate](/migrate/docs#cli-reylo-migrate) covers each command:

```terminal
Usage: reylo migrate <command> [flags]

Commands:
  init                     Start from this database
    --schema <name>        A schema to read (Postgres; public by default)
  new <name>               Write the next migration, from schema.sql or this database
    --drop <names>         Accept what it drops: tables and columns
    --rename <old>=<new>   Say a table or column was renamed
    --blocking             Accept a statement that blocks writes while it reads every row
  dev                      Take this database to the migrations, and lock them
  deploy                   Run what the lock lists, with no shadow database
    --dry-run              Try it on a shadow database, running nothing here
  status                   Check that this database and the files are in step
  lock                     Write the lock from this database's history
  history push             Record the migrations this database's schema has
  history pull             Write the migrations this database ran into files

Flags:
  --url <url>              The database, in place of direct_url
  --json                   Print the result as one JSON object
  -h, --help               Print this help
```

### `init`

Starts your migrations from an existing database:

```sh
reylo migrate init
reylo migrate init --schema app
```

### `new`

Writes the next migration, from your change to `schema.sql`:

```sh
reylo migrate new add_bio
reylo migrate new add_bio --drop users.bio
reylo migrate new add_bio --rename users.name=full_name
reylo migrate new add_bio --blocking
```

### `dev`

Takes your development database to your migrations, and writes the lock:

```sh
reylo migrate dev
```

### `deploy`

Runs the lock's pending migrations, with no shadow database:

```sh
reylo migrate deploy
reylo migrate deploy --dry-run
```

### `status`

Checks that a database and your files are in step, changing nothing:

```sh
reylo migrate status
reylo migrate status --url $PROD_URL
```

### `lock`

Writes the lock from your database's history:

```sh
reylo migrate lock
```

### `history push`

Records your migrations as run on a database that already has their schema:

```sh
reylo migrate history push --url $PROD_URL
```

### `history pull`

Writes your migration files from a database's history:

```sh
reylo migrate history pull --url $PROD_URL
```

## `reylo db`

Push `schema.sql` to a development database, reset it, wipe it or read its schema. [Reylo Migrate](/migrate/docs#db-push) covers each command:

```terminal
Usage: reylo db <command> [flags]

Commands:
  push                     Take this database to schema.sql, unrecorded
    --drop <names>         Accept what it drops: tables and columns
    --rename <old>=<new>   Say a table or column was renamed
    --force                Accept everything it drops
    --watch                Push again on each save
  reset                    Rebuild this database from the migrations
  wipe                     Delete every row, keeping the schema
  introspect               Print this database's schema as SQL
    --schema <name>        A schema to read (Postgres; public by default)

Flags:
  --url <url>              The database, in place of direct_url
  --json                   Print the result as one JSON object
  -h, --help               Print this help
```

### `push`

Takes your development database to `schema.sql`, with no migration:

```sh
reylo db push
reylo db push --watch
reylo db push --drop users.bio
reylo db push --force
```

### `reset`

Rebuilds your development database from your migrations:

```sh
reylo db reset
```

### `wipe`

Deletes every row, keeping the schema and the history:

```sh
reylo db wipe
```

### `introspect`

Prints your database's schema as SQL:

```sh
reylo db introspect
reylo db introspect --schema app
```

## `reylo run`

Runs SQL on the database as written, outside any migration's history.

It runs the statements you pass as text, then each `--file`, in order:

```terminal
$ reylo run 'alter table users add column bio text'
✓ alter table users add column bio text
```

On a SQLite file that isn't there, it refuses rather than make an empty database.

## `reylo play`

Serves the playground on this machine.

The page is a query editor. It shows Reylo's analysis of the query against your database at every keystroke, without running it. The `--no-open` flag leaves the browser closed, for a script or an agent. Either reads the same analysis as JSON:

```text
http://127.0.0.1:4983/?q=<sql>         the page, with a query in it
GET  /api/analyze?q=<sql>               a query's Params, Returns and diagnostics
POST /api/analyze  {"sql": "<sql>"}     the same
GET  /api/schema                        the tables, their columns, functions and types
```
